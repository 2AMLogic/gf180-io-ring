# esd_clamp

Pad-clamp diode sizing bench (issue #11, tracker #5). Sweeps `diode_nd2ps_06v0`
and `diode_pd2nw_06v0` over 33 areas (10 .. 1e5 µm², square, `pj = 4·sqrt(A)`)
in the `diode_typical`/`diode_ff`/`diode_ss` sections at −40/25/125 °C:

- forward I-V, 0 to 2 A (a current source drives the diode; the sweep reads V),
- reverse leakage at 5.5 V (`DVDD` max),
- junction capacitance at 0 V and 5.5 V reverse (ac, 1 MHz).

## Run

    sim/esd_clamp/run.sh                    # exit 0 = grid ran, derivation and wording check passed
    sim/esd_clamp/run.sh --bad-model-path   # negative control: must exit non-zero (1 = rejected as expected, 3 = accepted: control failed)

Three `klt sim` requests (forward dc, reverse dc, ac; 9/9/18 units) are
generated by `esd_clamp.py gen`. On a dispatch worker `KLT_SIM_BACKEND=batch`
sends them to the Spot fleet; a failed submit fails the run, there is no local
fallback. They use plain `.meas` cards only: the fleet runner image (klt 0.7.0
at the time of writing) rejects `analysis_steps`.

A passing run writes `records/<UTC stamp>/` with `record.md` (assumptions,
quoted ESD-evidence limitation, derived area per device per corner, binding
corner, budget sensitivity, capacitance and leakage, full I-V tables),
`summary.json`, the generated netlist and requests, and the three klt reports.
Records are append-only. `esd_clamp.py selftest` checks the derivation edge
case (no swept area meets the budget → reported, not interpolated) and the
wording check (`grep -iwE 'rated|qualified'` may match only the quoted
limitation); `run.sh` runs it first and again on the finished record.
